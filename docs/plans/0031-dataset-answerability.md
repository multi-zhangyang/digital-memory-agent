# 来源作答与训练题质量对照

关联任务：M5 准备可核验训练资料，H1 后台核验的恢复与真实交付。日期：2026-10-05。

状态：来源作答、最终问答核对与证据展示已实现，完成隔离真实模型对照和工程验证。部分语义与修复问题仍未解决；本轮没有切换个人数据目录对应的常驻服务，个人模型训练继续暂停。

## 问题与实现

原核验允许模型同时看到候选答案。程序能检查答案出现在冻结正文中、日期和配对答案一致，但无法由此判断所问人物、动作方向或关系正确。真实基线中，模型理由已说明两个问题考察不同事实，实际却提交 approve，使错误训练/评测配对进入文件。

本轮在现有独立核验 worker 中增加以下流程，Agent 与直接页面仍共用服务：

1. `memory/dataset-answer-checks.ts` 定义来源作答能力和验证规则，`integrations/pi/dataset-answer-checker.ts` 接入 Pi。请求只包含本条冻结记忆及问题，不包含候选答案、现有配对、修复决定或评测参考答案。
2. 程序按原文顺序提供编号片段，模型返回最短答案、可回答/有歧义/不支持、证据编号和同事实题组。证据从原文取回，不让模型重新抄写。验证覆盖、原文引用和题组一致性；人物、时间与关系的语义判断仍依赖模型。
3. 原审阅处理器对照来源作答后提交逐题决定。题干修订后重新作答；最终答案须一致，评测题与训练题须被来源作答识别为同一事实。无法完成时保留待核对或真实失败，审阅最多进行一次程序拒绝后的修复。
4. `DatasetLedger` 要求新的 processor 批准携带对应问答的 `answerCheck`。它随样本历史、备份和文件元数据保留，不进入训练 messages。后续显式修改或关联训练题变化使核验记录失效时，清除当前记录，保留历史。
5. 页面在现有 Accordion 内组合官方 shadcn Field，展示“来源作答”和“原文片段”。Agent 工具继续通过现有 AI Elements 展示实际输入、结果与失败。

已完成的来源作答按本作业、本条冻结来源及完整问题序列保存，修复或恢复可复用；问题改变则重新调用。协议升级为 3：1 是原基线，2 是本轮已放弃的抄写引用版本。旧协议未完成作业保留失败与既有结果，需新建当前协议核验；不把旧执行自动当成新协议结果。

用户及主 Agent 的显式审阅沿用既有授权和实际读取规则，没有强制增加来源作答。历史 ready 样本也不自动获得新核验记录；一次复核失败仍保留原样本状态。因此本改动保证的是**新后台审阅的提交条件**，不能声称所有历史或手动认可题均已通过新检查。多来源组合与叙述仍需单独核对。

## 调研与配置

按用户要求通过 Exa 搜索并读取一手论文及官方文档。采用来源与可回答性分层、隔离候选答案的核验方法，并用有标签的错误注入对照修复。参考 [Source2Synth](https://arxiv.org/abs/2409.08239) 的来源与可回答性分层，以及 [Chain-of-Verification](https://aclanthology.org/2024.findings-acl.212/) 隔离原候选答案的核验方法；同一模型的两次请求不等于独立裁判。没有把论文成绩套用到本项目。

真实调用使用现有 `openai-compatible/gpt-6-luna` 连接、Responses 协议、low 思考强度；连接最大输出 16384，来源作答最多 8000，审阅最多 6000。未修改供应商或 Harness 配置。连接密钥与 Exa 检索原始记录留在私有目录。

`examples/quality/dataset-answerability.json` 固定六条开发来源、六条原保留来源，每条含两道训练题和一道评测题；`dataset-answerability-confirmation.json` 另含四条后续对照来源。全部人物、经历和确认状态都是明确的虚构设定。**问题生成使用固定替身，来源作答和样本审阅才是真实模型调用。** 参考答案、风险标签不发送给模型，没有运行个人训练或完整主 Agent 交付效果实验。

## 真实结果

“可导出”只表示系统实际状态，不表示语义全对。每组每版只运行一次；原始失败全部保留，没有持续重试直到通过。

初版 v2 在原保留材料上退步：模型把原文的逗号改成句号，或把日期拼接到另一段文字，严格引用规则拒绝了两个来源的整批题。随后改成编号原文。该材料已用于诊断，v3 的 11/18 **只能作为开发回归**。后续 12 题是在 v3 固定后增加的作者可见材料，旧版在基线提交 `a9f4852` 的隔离工作树中执行；它也不是封闭盲测。

本轮代码助手逐题对照原文和最终实际问答，观察到：

- 原保留基线批准了“简沐买花的颜色 → 程芷拍花的颜色”的错误配对。后续基线再次批准“林夕读书会地点 → 苏砚领画册地点”的错误配对。两题答案相同，但人物、活动不同；两次理由都已指出问题。v3 都保留待核对，没有把它们送入评测文件。
- 原保留基线有三道冗长答案，其中一道从“归还对象”改问“借出者”，还丢失修书架事件限定。v3 在这组题上仍因修订泄露答案而整批失败，不能称为修复成功。
- v3 修复了后续材料的文件袋接收人与预订日期；原保留回归修复了交接接收人、两次烘焙课的次序，以及“开车”这一被来源明确否定的题干前提。
- 未植错控制题的保留数：原保留从 4/5 到 5/5，后续从 3/5 到 4/5。后续一次借车来源里的正确目的地题仍被同批失败连带阻止。

以上是开发阶段对照，**不是独立人工标注或独立准确率**。生成与核验来自同一模型家族的这一连接，存在相关错误；样本 ID 排序及模型采样也影响单次结果。没有评测全库事件消歧、检索召回、个人事实更新后的旧知识误用或训练效果。

## 下一步验收目标

1. **先减少整批连带失败。** 按训练题及其关联评测组成的依赖组提交，组内保持原子性；无关好题可保留。用结构化错误定位具体问题，修复后仍核对最终来源、配对、版本和重复题。验收同时看错误认可、正确控制题保留和调用开销，不单看通过条数。
2. **补足有依据的时间区间。** 当前日期规则不理解正文“2023年9月到2024年2月”覆盖“2023年10月”，会错误拒绝正确答案；继而修复又可能生成重复题。需要带主体、关系、有效区间和原文位置的时间表示，覆盖区间内、边界外、预订/发生日期区别及未知终点；不能单靠正文出现过某个日期。
3. **扩展多来源与纠正对照。** 在不同记录中加入相似人物、地点、周末和后续更正，分别给正确来源和通过检索取来源，定位理解错误与召回错误。测量旧事实继续使用、未确认观察被当作事实、未知信息编造，以及跨会话恢复的重复操作。

个人参数记忆待用户恢复训练安排后再进行冻结快照的基础模型、训练后闭卷与检索辅助对照；本轮来源作答没有证明任何信息已经学入个人模型参数。
