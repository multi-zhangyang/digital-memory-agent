## 问题与验收

阶段 24 的真实模型实测中，训练题询问杯子放在哪里，评测题询问碟子的特征；两题答案相同，所问关系不同。阶段 24 文档把这两题的用途顺序写反，本阶段重新读取原始报告后按实际 `intendedUse` 更正。生成器已经返回 `trainingIndex`，但保存样本时丢失了关联，交付检查仅查找任意相同答案。

本阶段保留版本化的训练题关联，使 Agent 与页面能逐对比较问题、答案和冻结来源。训练题修改后，关联评测题重新待核对；重新绑定和审阅保留历史。导出检查关联题的真实版本、状态、来源和答案，不把机械校验称为语义等价证明。未关联的旧评测题必须明确选择并核对后才能交付，原文件及历史不自动重写。

## 实现

生成器版本 3 保留真实 `trainingIndex`，服务保存 `evaluationOf: { id, version }`。`DatasetPairings` 检查同数据集、同冻结来源、当前训练题版本、训练用途、未排除状态和相同答案；这些是可核验的结构约束，不是语义裁判。旧评测缺失关联会在样本列表提示，并阻止评测文件下载和整体交付；已有数据和文件不在启动时自动改写。

`inspect_dataset` 同时返回关联训练题与同来源备选，计入输出大小预算并记录当前实际读取版本。`review_dataset` 可用短 ref 指定关联，只能在已读取训练题后批准评测题。事务按最终批次校验，允许训练和评测同时修订。训练题问答或排除变化时，未一起核对的评测题自动进入 review，当前认可被撤销，旧版本继续保留；仅批准未改问答时更新版本引用、保留旧审阅。回执区分显式决定和传播，传播不伪装成新用户确认。

相同策略及来源的重建样本复用关联到新数据集的实际训练题 ID 和版本；旧关联版本不一致时不复用。生成器版本改变则重新生成并待审，不沿用不具备新关联信息的旧问法。`evaluationOf` 随评测及待审文件保存，清单标明关联规则版本。旧重建验收脚本区分同策略复用与策略升级后重新生成，不将生成器版本变化误报为重复生成。

页面组合既有 shadcn Accordion、Field、Select、Input、Textarea 和 Alert，展示关联训练题的实际问题、答案和版本，允许选择、修订或排除。Agent 输入、输出、拒绝和修正继续进入官方 AI Elements Tool 展示和会话历史；没有另建控件或加入解释性 UI 文案。
