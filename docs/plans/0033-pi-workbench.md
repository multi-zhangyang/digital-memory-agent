## 已实现

- `PiTranscript` 与共享事件归约器保留 message/turn/content/tool 身份；最终消息补全漏掉的流式片段，并保留并行和嵌套工具结果。Pi 的 entry ID 在实际追加后关联，原始 JSONL 继续作为模型会话依据。
- 执行时间线按消息顺序组合 Message、Reasoning、Tool、Checkpoint、Task；参数流、错误和当前调用自动展开。工具调用不再藏在统一的“执行记录”开关后。
- 桌面默认对话与工作区双栏，文件、终端、改动、成果、来源和训练文件使用持久标签；已访问页面保持挂载，文件草稿可切换、保存和恢复。来源详情移除嵌入场景中的第二层导航。移动端复用同一工作区与 Sheet。
- 默认 50 组消息的服务端历史分页与 SSE 游标各自管理；加载旧页保持滚动位置，同时间戳按服务端顺序排列，切回会话先显示缓存再对账。
- 原生会话树包含工具结果和压缩节点，区分原会话内继续与新建分支，展示当前路径。停止等实际取消完成后才结束，保留取消期间最后到达的结果。队列可整体退回编辑器，handled、消费和退回分别记录。
- Web 扩展对话、预填、文字 Widget、状态与编辑器适配持久化；超时/取消不会伪造用户拒绝或确认。MCP 可以 direct 或 deferred 暴露，后者使用原生 `tool_search`，能力面板展示实际加载与激活状态。
- `deliver_dataset` 的真实回执在同一工作区展示文件、条数、版本、用途、样本和记忆来源；版本失效时要求重新核验。独立业务服务与直接页面继续共用规则。

## 发现并修复的核心问题

第一次真实模型验证把无日期地点的照片并进午餐，并在增量归组中返回无效关联。失败保存在 `.data/evaluations/living-memory-live-lu1zHU/report.json`，没有改写成成功。

补充了服务端归组约束：无日期地点、没有共同原件的视觉观察不能借其他记录获得活动身份；每组必须包含本批观察，不能遗漏或重复成员、违反用户拆分或跨已知日期合并。一次校验失败可携带具体原因和上次提案修正；再次失败则保留作业失败。修正不绕过原件或版本检查。执行计划也支持引用本轮实际读取的 `asset:<id>`，仅选中资料仍不能充作读取结果。

UI 验证另外发现并修复了相同时间戳分页错序、重复详情导航和取消中的结果丢失风险；Web 绑定 Pi 时对 Theme 的要求已通过公开文字主题兼容，不再让终端主题接口阻断整个会话。
