# 打开本地工作目录

> 历史阶段记录：保留当时的决策、实测和限制。当前产品以 [产品定义](../product.md)、[架构](../architecture.md) 和 [Harness 重构计划](0018-harness-refactor.md) 为准。

## 目标

从 WebUI 浏览或粘贴 Agent 所在设备上的已有文件夹。项目保存真实目录；Pi、文件编辑、隔离终端和检查点使用同一目录。继续支持应用管理的空白项目。

## 实现范围

- shadcn/ui 目录选择对话框：路径输入、上级目录、常用位置、筛选、隐藏目录、分批加载。
- 打开已有目录并记住项目，规范化路径后去重；旧任务继续关联原项目。
- WSL 支持 Windows 盘符路径以及当前发行版的 UNC 路径。
- 保留既有路径和权限边界，应用的私人数据不进入项目工具、快照或终端挂载。
- 原目录离线或被移动时明确报错，不创建同名空目录。
- 覆盖实际目录的读写、Pi 工具与脚本执行、回退、恢复和浏览器选择流程。

## 参考

使用 Exa 查到的 [T3 Code 目录浏览实现](https://github.com/pingdotgg/t3code/pull/2024) 在 Web 中通过后端文件系统浏览 API 选择项目路径。浏览器上传目录得到的是文件及相对路径，不能据此为 Agent 提供主机上的工作目录。

## 验证

- `pnpm typecheck`、生产构建通过。
- `pnpm test`：30 项后端测试通过。新增场景验证外部原文件读写、真实 Pi + bubblewrap 执行、AGENTS.md 加载、重启后的会话及回退、目录去重、路径和权限错误、旧项目迁移、应用私人目录排除，以及重叠目录的执行互斥。
- 浏览器原有 15 项场景通过；新增的两项 `local-workspaces.spec.ts` 在生产构建中通过。覆盖目录浏览、名称筛选、隐藏目录、上级目录、直接粘贴、原文件编辑和脚本结果、刷新/旧任务恢复、相同目录复用、手机界面和取消。
- 用可控的首次目录响应验证：输入框已获得焦点时到达的后台结果不覆盖用户输入。目录筛选使用官方 Command 的标签关联，支持键盘和辅助技术。
- 模型仅在测试中使用本地供应商替身；Pi、文件系统、SQLite 和沙箱为实际执行。未调用付费模型。
- 更新后的生产服务已启动；实际页面的桌面/手机目录浏览检查通过，浏览器无脚本错误，健康接口返回 200，旧项目均具有真实目录信息。

## 已交付

侧栏「打开文件夹」、新任务页项目入口和 `Ctrl/Cmd+O` 调用同一个按需加载的 shadcn/ui 目录选择对话框。文件面板展示及复制真实工作目录，项目设置也显示目录。支持已挂载的 Windows 盘符路径，旧任务不会因打开另一个文件夹而改变执行位置。阶段内容未写入 AGENTS.md。
