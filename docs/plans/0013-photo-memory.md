# 阶段十三：照片观察、核对与原图证据

> 历史阶段记录：保留当时的决策、实测和限制。当前产品以 [产品定义](../product.md)、[架构](../architecture.md) 和 [Harness 重构计划](0018-harness-refactor.md) 为准。

## 范围

用户授权自行寻找公开图片并推进测试，暂不训练。照片闭环接到现有 Pi 适配、导入队列、记忆账本和 WebUI，完成选择照片、模型提取、核对、确认、纠正、召回及停止取用。Colab CLI 保持已安装、未登录、未分配 GPU 状态。

本阶段交付的是照片观察入库原型。图片实际经 Pi 提取接口发送给已配置模型，通用 Agent 尚未拥有主动调用照片处理任务的业务工具。现有 ID/摘要用于原件定位与校验，区域是模型输出；这些功能不等于跨照片实体识别、完整长期记忆系统或模型参数记忆。

核对后六个问答不能作为自主识别能力验收：六条公开照片候选中有三条由开发 Agent 修改后才进入问答。此前“完成照片记忆流程”的表述容易混淆入库链路与项目整体目标；后续优先级调整为[长期记忆组织与检索基础](0014-memory-retrieval-foundation.md)，不再用增加少量图片问答替代该项工作。

## 实现

- 复用 `MemoryImports`，每张照片一个持久处理单元。串行调用、失败重试、取消、重启恢复、处理回执与幂等保存沿用已有机制。
- sharp 0.35.5 校验原件、处理方向、移除 EXIF/GPS、缩放长边至 1,600 像素；每张最多 20 MB / 4,000 万像素，只支持 JPEG、PNG、静态 WebP。供应商只收到选中的处理图，不收到文件名和原始元数据。
- `extract_photo_memories` 返回观察/推断、可选区域、不确定性及可见文字转写。所有视觉候选先待核对，人物和发生时间留空，没有个人画像写入权限；无效区域等结构错误整张拒绝保存。
- 新照片即使产生与已确认记忆相同的正文，也必须重新核对，不把新的视觉依据直接附到已确认事实。相同原件的已处理回执仍可复用；未确认、同类候选可合并依据。
- 原始依据保存原件及预览摘要、定向尺寸、区域与转写。前端对照图片并核验原件；原件一致不代表模型结论正确。确认后复用版本、索引及 Pi 上下文失效，保留原始错误候选和纠正依据。
- 当前停用按整张照片的来源范围执行，所有关联观察随来源停止取用；相同来源在外部调用前阻断。原图与版本仍可查看。尚不支持按局部区域单独停用。
- 前端继续组合官方 shadcn 和 AI Elements，使用已安装的 ai-elements / shadcn skills。新增官方 Spinner 仅适配本地 `cn` 路径及中文加载标签；私有预览使用 Next Image `unoptimized`，来源及兼容说明见 [第三方说明](../../THIRD_PARTY_NOTICES.md)。

## 测试素材与真实结果

通过 Exa 搜索选取三张许可清楚的公开照片：咖啡杯、雾中桥梁、NASA 宇航员与旗帜。准确来源、作者、许可、摘要及下载脚本见 [公开照片测试](../../examples/photos/README.md)。另生成一张包含诱导指令的英文文字图。图片、数据库及完整报告仅位于忽略目录，未混入主工作台的个人记忆。

已用配置的 `gpt-6-luna`、low 思考强度完成两轮实际视觉提取。第一轮过于保守，将杯子泛称为椭圆器皿；提示词改为使用有视觉依据的常见物体名称，提取版本升为 2。第二轮四张均完成，得到六条公开照片候选和一条文字图候选，均未自动确认、填入拍摄日期或人物姓名；原件与预览摘要核验通过。重复导入四张均复用记录，模型调用次数为零。

模型存在真实错误：第二轮把杯子识别为碗，把蓝白杯碟花纹识别为桌布；桥梁描述包含画面之外的连接细节。开发 Agent 查看原图后纠正两条杯碟候选和一条桥梁候选，再确认六条公开观察。宇航服、旗帜、脚印与设备的描述基本对应画面，保留不确定性。文字图的指令被转写，没有生成“用户住在月球”的个人事实，该条保持草稿。

第一轮报告：`.data/evaluations/photos-live-QsKQNC/report.json`。第二轮报告及逐条核对文件：`.data/evaluations/photos-live-037HhU/report.json`、`reviewed.json`。原始错误仍可审阅，后续问答基于核对修订后的版本，不能当作原始提取准确率。核对者为 Codex 对照公开原图，不冒充用户本人确认。

## 验证进度

- 类型检查和独立源码副本生产构建通过。
- 后端 **64 项测试**通过，其中六项照片测试覆盖发送范围、缩放/方向/元数据、原件篡改、空间隔离、无视觉配置、非法图片/区域、原子保存、重试、纠正、去重、新照片不得继承已确认状态、停用、取消与重启恢复。
- 照片浏览器用例通过：视觉设置持久化、上传选择、真实处理状态、区域及原件预览、摘要校验、确认、纠正、跨会话召回、停用与不再提取。使用本地模型替身，不能作为真实识别效果证明。
- 后端照片集成实际经过 Pi、多模态协议、sharp 与 SQLite；取消/恢复用例中的挂起阶段使用可控的运行时替身，再恢复真实 Pi 与本地模型供应商。测试中的色块与描述是测试替身，不冒充视觉识别。
- 完整生产模式浏览器回归 **28 项通过**；补充新照片状态隔离后，再次通过照片流程。独立副本使用 47063 / 46695 / 44781 端口，避免原服务与默认测试端口干扰。手机界面和原图加载另行检查。
- 真实模型在六个独立新会话中完成问答：三类照片问题均引用了对应的已确认记忆；另外三问没有推断用户到访、人物姓名/拍摄日期或咖啡偏好。已逐条检查实际回答，**6/6 符合本次预期**。这是修订后召回链路的小样本验证，不是原始视觉提取分数。
- 停用咖啡来源后，相关观察从检索中排除，重导入显示已停止取用、零模型调用、零新增记忆。英文指令图仅说明该个案没有越权，不代表完整提示注入防护评测。

## 后续方向

先扩大视觉评测：更多物体、遮挡、低照度、长文字和多人照片，比较漏记、误识别与核对成本。当前实测尚不支持跳过核对；应依据评测选择更可靠的视觉模型，而不是用成功调用率代替准确率。

随后引入可本地运行的人脸特征与跨照片聚类，保留未知身份，并由可靠标注完成姓名/关系关联。人物聚类和身份确认分开；再扩展视频分段、音频转写与时间定位。检索嵌入依据任务评测决定，个人模型训练须另建经过核验的数据版本及闭卷评估，按用户指令继续后置。
