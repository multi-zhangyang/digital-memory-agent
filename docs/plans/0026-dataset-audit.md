# 后台批量核验训练问答

关联任务：M5 准备个人模型训练数据，H1 可审阅、可恢复的 Agent 执行。

状态：功能、真实 Agent、相关回归、非空恢复、生产构建和本机启用完成。个人模型训练保持暂停。

## 用户任务与验收

用户提交一批确认材料后，Agent 应实际生成、核验并交付训练文件。逐页检查适合具体疑点，整批重复核验交由独立后台服务处理，不要求主 Agent 保持在线并逐题指挥。

核验按冻结来源分批比较问答、人物与动作方向、时间限定、答案片段，以及训练题和评测题所问的关系。每题保存认可、修订、排除或待核对决定及依据；保留真实模型、原版本、作业及调用记录。结果为模型审阅，不能提高个人事实确认等级，也不能充当独立质量准确率。

作业受理、实际进度、失败、取消、重试与文件重新导出应在会话和页面使用同一业务状态。停止服务后恢复未完成来源，已提交样本不重复修订。模型只接收本批冻结正文和相关题目；来源过期、版本冲突或程序拒绝不能写入半批结果。

## 实现范围

新增 `audit_dataset` 与 `dataset-audit` 作业驱动、直接 API 和数据集核验入口。核验模型单独配置；默认仅处理待审问答及受影响评测，也可明确选择全部问答。保留排除样本和未选择的审阅决定。叙述与多来源组合显示需单独核对，不声称已经支持。

后台使用 Pi 模型接口的专用核验协议。每个来源的决定通过已有版本化样本事务保存，训练/评测在最终批次核对，模型审阅记录与历史随样本、导出和 SQLite 归档保留。程序拒绝后的修复仅追加一次模型尝试；失败保留实际尝试与原样本。作业事件写入持久化事件表，Harness 自动取得完成结果。

前端组合官方 shadcn Select、ToggleGroup、Progress、Table、Field、Badge 和既有控件；核验状态、统计和每题依据为真实业务数据。会话继续使用官方 AI Elements Tool 和 Task 展示调用与作业，不添加解释性流程文案。
