# 特征服务、检索与恢复

## 用户配置服务

在「设置 → 模型连接 → 检索与人物服务」分别配置文字嵌入、图像嵌入和人脸特征的协议、地址、模型名称、版本标记与可选密钥。三项默认关闭，可以接入同一个服务，也可以使用不同供应商。项目提供调用接口、索引与业务规则；模型选型、权重、部署设备及 GPU 调度由所接服务管理。

文字支持 OpenAI 兼容 `/embeddings` 和 Memory Features v1。图像、人脸使用 [Memory Features v1 接入协议](feature-service-protocol.md)：图像通道需同时提供图片编码和文字找图；人脸通道提供检测区域、质量状态和身份特征。兼容协议不代表任意服务开箱即用；不兼容的模型服务器需要自行增加协议适配。

「测试连接」使用固定文字和程序生成的空白图片校验接口，不读取资料库，不保存配置；成功不代表模型准确率已经验证。「保存」立即应用启停和连接参数，无需重启。状态区显示未启用、正在连接、已连接或不可用。当前启用的任一通道连接探测失败，整套特征处理标为不可用，关键词检索仍可用；可修复或停用故障通道后重试。

启用连接后，后台会将对应的已入库资料、记忆片段及查询发送到配置的地址。图片先在本机按 EXIF 定向、去除 EXIF/GPS 等附加信息、缩至最长边 1600 像素，再发送 JPEG。拍摄时间、时区偏移与是否存在 GPS 仅作为本机未核验元信息保留，不用导入时间补齐拍摄时间。只启用文字不会发送图片；只启用人脸不会调用文字或图文编码。

密钥仅保存在服务端数据目录的 `feature-models.json`（0600），API 只返回是否已保存。留空保留密钥，显式清除才删除；更换地址后不会自动把旧密钥带过去。HTTP 请求拒绝重定向，限制时长和响应大小，错误不回传供应商的私密输入或密钥。

## 版本与索引

业务层使用 `FeatureProcessor` 能力接口，不引用具体模型名称、维度或推理框架。向量维度从接口探测，支持 1–8192 维；存储按维度建表，按空间、能力和编码器指纹隔离。旧表从实际 SQLite 定义读取维度，保留原数据。模型、版本标记、接口地址或编码空间变更后排队重建索引；旧模型索引保留，可供切回相同版本后复用或重建，检索只访问当前指纹。

更换同名权重或预处理后必须更新版本标记；Memory Features v1 服务还须更新每次响应中的 `revision`。同维度不能证明向量空间相同。只在服务声明同一 `spaceId` 且地址、模型、版本、维度一致时复用文字与图像的查询编码。资料类型过滤和排名融合独立保留。

索引作业由后台服务维护，无需主 Agent 在线。来源、当前版本、空间、时间、人物和停用规则在候选截断前实施。未确认观察可作为原件证据；`search_memories` 仍只返回符合确认规则的事实。索引策略在「设置 → 个人记忆」，模型接口在「设置 → 模型连接」。

长文本按有重叠的片段处理；超出覆盖上限或服务明确报告截断时作业失败。OpenAI 标准嵌入响应没有逐条 token 数及截断状态，记录为未知，须选择会拒绝超长输入而不静默截断的服务。这项接口限制不等于已验证全文覆盖。

## 人物与视频

人物候选相似度阈值和与次优候选的差值可在设置页调整，需要按实际模型和资料校准。初始参数只是候选规则，不是身份概率。参数变更不会撤销原有候选、用户确认、合并或拆分决定；新出现的身份仍待可靠依据确认。

人脸编码器拥有独立指纹，单独更换文字或图像嵌入模型不会改变同一人脸服务生成的观察标识。更换人脸模型时在新空间提取特征，旧观察和人工确认继续保留；新模型结果不会自动继承旧身份，也不进行跨模型向量匹配。

视频以抽样帧调用用户配置的图像／人脸接口；默认间隔 10 秒、最多 120 帧，不含音频转写。原件、实际帧时点、模型和失败回执保留；成功帧可复用，失败帧可重试。抽样不能证明没有遗漏短暂事件。

## 可选旧版本地适配与选型参考

`services/memory-worker/` 保留已有 CPU Python 适配作为兼容实现和评测基线，不是项目默认模型。需要使用时显式安装并设置两个环境变量：

```bash
UV_PROJECT_ENVIRONMENT="$PWD/.data/memory-worker/venv" uv sync --project services/memory-worker --frozen
python3 services/memory-worker/setup_models.py --destination .data/memory-worker/models
MEMORY_WORKER_PYTHON="$PWD/.data/memory-worker/venv/bin/python" MEMORY_FEATURE_MODELS="$PWD/.data/memory-worker/models" pnpm dev
```

旧适配固定 E5、SigLIP2、YuNet/SFace，其模型清单和依赖锁仅属于该适配。应用不再自动发现权重并启用它；保存界面特征配置后，界面配置优先，不会因停用 HTTP 服务而回落到旧本地模型。`MEMORY_LOCAL_FEATURES=off` 可禁止旧适配。

真实模型的 CPU/GPU 对照见[统一嵌入评估](plans/0035-unified-embedding-evaluation.md)与[人脸 GPU 评估](plans/0036-face-gpu-evaluation.md)，复现入口见 [quality README](../examples/quality/README.md)。这些是特定模型、机器和小样本的选型参考，不是所有安装者的默认配置，也不证明准确率普遍提高。人物阈值和困难照片仍需独立验证。

## 数据集与恢复

`build_dataset` 和 WebUI「数据集」调用同一个服务：冻结全部合格记忆版本 → 逐条核验 → 模板或独立模型生成问题 → 样本核对与导出。模板支持原文叙述和同一明确事件的少量组合；模型生成训练问法及针对相同已知答案的评测问法。清单保存每条输入的状态、排除原因与依赖，不用相关性 Top-K 近似全量。

推断、未解决的不确定性、待审冲突、不可核验来源和完全重复记录不进入可训练样本。用户确认、策略接受、来源未知分别记录；策略接受与模型生成问题需要样本核对。答案必须逐字来自当前确认正文，评测答案应与训练题一致，问法不得重复。这个划分测试同一事实的不同问法，不是未知事实保留集。引句匹配不证明问题语义成立；[阶段十七](plans/0017-dataset-questions.md) 的两处语义错误仍然保留。

导出 `training.jsonl` 仅含可用训练样本，`review.jsonl` 保留待审样本，`manifest.json` 记录全部冻结输入、计数和摘要；模型生成任务另导出 `evaluation.jsonl`，其问法不混入训练。未来训练器读取 `messages`，评测器读取 `question / expectedAnswer`；来源引句及依赖属于核验元数据，不能把旧值拼入训练回答。确认样本保存新版本，再生成导出文件。

来源、人物、实体、事件或记忆版本改变会标记受影响样本和数据集过期；已登记模型版本只标记“受影响”，权重不会随记录修订自动更新。个人模型训练与权重交付尚未实现。恢复过程中断后继续未完成输入；取消保留已提交结果。下载前重新核验原件和导出摘要。

先停止应用服务，再进行记忆备份；目录参数使用绝对路径：

```bash
pnpm --filter @memory/agent archive:memory backup /资料目录 /新的备份目录
pnpm --filter @memory/agent archive:memory restore /备份目录 /新的恢复目录
```

备份包含 SQLite、原件、已完成的数据集文件和 Pi 会话，逐文件记录摘要。复制期间检测到数据库或文件变更则失败；恢复仅写入新目录，验证清单、文件摘要、数据库完整性和外键。恢复会把项目目录绑定重设到新实例的只读工作区，避免错误指向原实例文件。

这是记忆备份，不包含模型连接密钥、Harness 私密配置、编码器缓存、项目文件或训练权重。完整工作环境应在停服后另行备份这些内容；特征服务按用户自己的部署配置恢复。恢复后配置 `MEMORY_DATA_DIR`、重新连接模型，并明确重新打开所需项目。
