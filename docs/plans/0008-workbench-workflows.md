# 项目、文件上下文与审阅工作流

## 目标

把通用 Agent 工作台的项目切换、输入、文件浏览和变更审阅连接起来。沿用黑白主题、shadcn/ui、AI Elements 和真实 Pi 会话，不增加无实现的入口。

## 已实施

- 项目作为侧栏主层级，紧凑显示各项目的任务与真实执行状态。
- 输入框内完成 `@` 项目文件引用和 `/` 命令选择，保留光标、草稿和中文输入。
- 服务端校验文件引用，按需提供有大小上限的真实文件内容；历史改动引用保持对应版本。
- 快速打开文件、命令菜单和常用快捷键。
- 变更面板选择文件后集中审阅；审阅意见连同文件版本加入当前草稿，由用户发送。
- 保留并验证执行中补充、排队、权限、文件回退和本地工作目录。

## 设计依据

通过 Exa 检索，再阅读官方文档：

- [Codex 命令与快捷键](https://learn.chatgpt.com/docs/reference/commands)：命令菜单、打开目录、任务和面板切换。
- [Claude Code 桌面工作流](https://code.claude.com/docs/en/desktop)：项目会话、文件引用、执行中指导及变更审阅。
- [Claude Code 命令](https://code.claude.com/docs/en/commands)：按当前可用能力提供命令入口。

借鉴操作组织，不将桌面专属能力、Git 功能或完整终端交互冒充为当前 WebUI 已有能力。

## 验证

- `pnpm typecheck` 与生产构建通过。
- 后端 34 项测试通过。新增测试覆盖真实 Pi 收到所选文件正文、未选择文件不被加载、引用截断、历史版本不被磁盘后续内容替代、删除文件的历史内容，以及越界、符号链接、私人应用数据和跨项目引用拒绝。
- 完整浏览器回归 20 项通过。随后对输入法确认键、长任务名溢出、文件列表键盘选择和鼠标悬停做最后调整，相关 5 项浏览器流程再次通过。覆盖文件引用、命令补全、快速打开、项目草稿、审阅意见、已查看标记、分栏恢复、历史差异、编辑冲突与实际文件回退。
- 模型协议在测试中使用本地替身；Pi、SQLite、文件系统与 bubblewrap 为实际执行。本轮没有调用付费模型。
- 生产模式的本机输入基准：新任务页输入到下一帧中位数 15.2ms / P95 16.3ms；60 轮模拟历史首次渲染 20 轮，中位数 15.5ms / P95 15.9ms。该测量包含浏览器自动化开销，不是线上 INP；长会话初始化仍记录一次约 142ms 的主线程长任务，不将输入流畅等同于所有阶段零卡顿。报告保存在忽略目录 `test-results/performance/phase8-workflows/report.json`。
- 生产服务已启动，实际页面与健康接口均返回 200。桌面命令菜单、快速打开和手机布局检查通过，浏览器脚本错误为零，手机页面无水平溢出。截图与结果保存在 `test-results/phase8-production/`。
- 检查 153 个仓库文件，没有真实供应商或 Exa 凭据匹配，私人数据未进入 Git。

## 交付

项目侧栏、输入上下文、文件浏览和版本审阅接在同一工作流中。审阅意见只追加到待发送草稿；工作台命令保留附件，重新运行旧请求不清空正在写的新内容。阶段内容独立记录于本文件。
