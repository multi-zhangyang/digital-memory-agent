# digital memory：Agent 工作台设计研究

研究日期：2026-10-03。状态：设计研究存档。2026-10-03 已按此方向实现首期工作台，实际交付范围与验收结果见 [第三阶段记录](../plans/0003-agent-workspace.md)；本文中的后续设计不代表全部已实现。

通过 Exa 搜索官方产品资料、组件文档和公开界面示例，并核对当前工程。查看了 v0、Manus、Mem、Pieces 的官方示例图片；没有登录这些产品验证完整交互。公开示例可能来自较早版本，本文借鉴其交互方式，不将截图视作当前产品全貌。检索原始结果与参考图片保存在被 Git 忽略的 `.data/design-research/`。

## 1. 当前版本的问题

现有版本完成了基础连接和文件存储，但还没有形成围绕个人经历工作的产品。换成官方组件只解决了控件的一致性，以下问题仍然存在：

| 现状 | 对用户的影响 | 改造目标 |
| --- | --- | --- |
| 首屏只有通用问候、聊天框、查找与读取两个建议 | 看不出如何开始整理个人经历 | 从导入资料、继续任务和查看待核对内容开始 |
| 聊天附件入口跳转资料库，输入框禁用附件 | 用户无法自然地指定“处理这几份资料”，切换页面还会丢失局部草稿状态 | 在输入框直接导入、选取、预览和移除本次资料 |
| 右侧面板只是全库文件列表，点击后离开对话 | 资料与当前任务没有明确关系，无法边看边问 | 当前任务资料与结果的可调整预览区 |
| 每次工具调用都是独立卡片，参数以 JSON 展示 | 用户需要自己从技术日志推断 Agent 正在做什么 | 执行摘要、步骤、证据、技术详情分层展示 |
| 会话只有运行中布尔值，流与请求连接绑定 | 缺少稳定的任务记录、等待输入状态和断线恢复语义 | 持久化运行记录与可重放事件流 |
| 只有复制回复，没有结果对象 | 整理结果被埋在聊天里，不能独立修订或再次引用 | 有来源和版本的文档、事件清单与记忆草稿 |
| 记忆、人物、训练都只显示未启用 | 菜单数量制造了产品完整的错觉 | 以真正可用的工作流组织导航，后续能力按完整流程启用 |
| 大片空白、重复边框、密集的 10–11px 文字 | 信息少但仍费力，缺少阅读层级 | 正常字号、明确主次、根据任务状态安排密度 |

这里的根本缺口同时涉及产品交互与 harness。增加按钮和装饰性状态不能补齐数据流。

## 2. 官方参考及取舍

### Vercel / v0：操作与结果并排

v0 的公开文档和 Design mode 示例让用户在指令、预览与编辑之间保持上下文；附件可以从输入框上传、拖入或粘贴。其项目文档提供跨会话和项目的命令面板搜索。[Design mode](https://v0.app/docs/design-mode)、[附件](https://v0.app/docs/images-and-videos)、[项目与搜索](https://v0.app/docs/projects)。

应用到本项目：对话旁边展示当前资料或整理结果，选中的文字、图片和未来的视频片段可以带回输入框；导航和搜索不清空工作状态。借鉴分区、密度和就地操作，不搬入代码编辑器、部署按钮或示例业务仪表盘。

Vercel 的 Geist 文档把颜色、排版、材质与网格作为共同基础。这里借鉴其层级与一致性，继续使用用户指定的 shadcn/ui，不另外引入一套基础组件。[Geist](https://vercel.com/geist/introduction)、[Typography](https://vercel.com/geist/typography)。

### Manus：任务有持续的上下文和执行状态

Manus Projects 将指令与文件放在持久工作区，新任务复用这些上下文。公开任务接口区分运行、等待输入、停止、错误，并传递计划、工具事件与输出附件。[Projects](https://manus.im/docs/features/projects)、[官方界面示例](https://www.manus.im/blog/projects-connectors)、[任务生命周期](https://open.manus.ai/docs/v2/task-lifecycle)、[事件类型](https://open.manus.ai/docs/v2/task.listMessages)。

应用到本项目：一次整理任务应有资料范围、目标、步骤、结果和待处理问题。用户可以离开任务再回来，执行记录不会丢失。我们不默认接入其云端服务，也不为增加功能数量加入邮件、浏览器和任意 Shell 权限。

### NotebookLM：资料范围与答案证据

Google 的笔记产品把来源、Chat 与 Studio 输出区分开；可以选择用于提问的资料，回答带有来源引用，结果可以保存为笔记。[创建笔记本](https://support.google.com/notebooklm/answer/16206563?hl=en)、[来源](https://support.google.com/notebooklm/answer/16215270)、[引用能力](https://support.google.com/notebooklm/answer/16164461?hl=en)、[保存笔记](https://support.google.com/notebooklm/answer/16262519)。

应用到本项目：用户能看到本次引用了哪些原件，点开结论能定位其证据。模型生成的结果保存为草稿；是否能作为个人事实使用，由证据和确认状态决定。无需照搬其音频节目、演示文稿等输出类型。

### Mem / Pieces：时间、关联与持续可用的记忆

Mem 的 Heads Up 在当前笔记旁展示相关历史和主题；Collections 允许一条笔记属于多个集合。Pieces 的 Timeline 按日期组织活动，支持筛选和打开详细内容，其自动摘要带有回到相关资源的链接。[Heads Up](https://get.mem.ai/features/heads-up)、[Collections](https://help.mem.ai/features/collections)、[Timeline](https://docs.pieces.app/products/desktop/timeline)、[摘要](https://docs.pieces.app/products/desktop/timeline/ltm-rollups)。

应用到本项目：同一素材可关联多个人物、事件和时间段；打开某次经历时能看到相关记录。记忆需要可查看、修改和追溯的对象。本项目不因此默认开启持续录屏或后台采集。

### Claude：结果可以独立于聊天存在

Claude 的公开 Artifacts 文档说明，生成的交互结果可以保存并从独立入口重新打开。[Artifacts](https://support.claude.com/en/articles/14729249-use-artifacts-in-claude-cowork)。

应用到本项目：时间线、整理笔记和记忆草稿应在工作区里独立打开、修订和引用。首期优先支持受控的 Markdown 与结构化结果，不执行模型任意生成的应用代码。

## 3. 目标工作台

产品的主要对象是资料、任务、记忆和结果。聊天负责发出指令与协作，其他对象具有独立身份和状态。

桌面工作区布局如下；名称描述设计目标，不代表现有功能已实现。

| 左侧导航 | 中央任务区 | 右侧工作区 |
| --- | --- | --- |
| 新任务、全局搜索 | 任务名称、所属资料集合、当前状态 | 资料 / 结果 / 记忆 |
| 工作台、资料库、记忆 | 用户指令与本次附加资料 | 原件预览与证据定位 |
| 进行中、待处理、最近任务 | 可折叠执行进度、关键问题 | 整理结果、修订和版本 |
| 收藏的集合或任务 | 回答、来源引用、结果入口 | 本次取用的相关记忆 |
| 设置 | 固定输入框与紧凑运行设置 | 按当前操作打开、切换或收起 |

右区使用可调整分栏，不常驻一份与任务无关的全库目录。小屏幕改用 Sheet 或整页切换；保留当前任务、草稿和资料选择。

### 输入框

- 直接上传和拖入文件；从资料库选择已有资料，显示缩略图、名称、上传进度和移除操作。
- 通过 `@` 搜索并引用已有资料；人物与记忆引用随相应后端能力开放。
- 输入旁提供模型与本次思考强度选择；地址、密钥等连接参数留在设置页。
- 显示本次资料范围与可用工具组，配置必须实际约束服务端执行。
- 保留草稿；支持换行、停止、失败重试，补充指令进入明确的待处理队列。
- 上下文信息展开后显示已知的使用量和组成。供应商没返回的数据标记未知；不拿累计 token 当成当前上下文，不展示无定价依据的费用。

首个完整流程先覆盖可实际读取的文字资料。图片和视频可以上传、预览，但在解析能力接通前，不宣称 Agent 已理解它们。

### 执行过程

默认让用户看到“正在做什么、做到哪一步、需要我做什么”。一组相关工具调用归入一个可展开步骤；完成的步骤折叠，失败和等待输入的步骤展开。原始参数、输出与错误保留在详情层。

只显示真实计划或已观测步骤。没有明确计划时只展示活动记录，不根据时间伪造进度百分比；不把生成的思考文本当成事实或完整内部推理。

运行状态应覆盖：排队、执行中、等待输入、成功、失败、已停止。停止与成功分开；重试产生可关联的新执行记录。后台继续、断线重连和恢复执行均需要 harness 支持后才能在界面承诺。

### 结果与证据

Agent 交付可打开的整理笔记、事件清单或记忆草稿。结果入口留在对话中，正文在右区显示，支持修订、继续讨论、导出及版本记录。

引用关联真实资料 ID、版本与定位信息：文字段落或字节范围，未来扩展到图片区域和视频时间段。用户点引用即可查看原件。模型不得编造有效来源 ID；服务端验证引用存在并属于可用范围。

### Agent 对“我”的记忆

记忆页面应提供概览、时间线、人物与待核对内容。每条记忆包含内容、发生时间、来源、确认状态与修改记录。本次回答取用了哪些记忆，也可在工作区查看。

用户直接陈述的信息保留其会话来源；资料中提取的观察与模型推断分别记录。系统可自动整理和生成草稿，矛盾信息、身份关联和重要不确定项才进入待核对列表，不要求用户逐条手工标注所有素材。

人物界面的目标是查看同一人物关联的素材、合并或拆分误归组、一次确认身份并追踪影响。检测到人脸、聚类相似人物、知道真实姓名是不同能力，界面需允许“未知人物”。

嵌入模型仍然推后。第一步可用 SQLite 的关键词、全文检索与时间/来源条件召回有限记忆，随后通过适配层引入嵌入后端。上下文压缩不替代这份持久记录。

## 4. 四种必须一起设计的页面状态

| 状态 | 主内容 | 主要操作 |
| --- | --- | --- |
| 首次使用 | 导入入口、可直接执行的起始动作 | 导入并开始任务 |
| 已有资料、尚未执行 | 选中的资料、最近任务、实际待处理项 | 设置目标并开始 |
| 正在执行 | 当前步骤、相关资料、等待输入或错误 | 补充、查看原件、停止 |
| 执行结束 | 结果、来源、待核对记忆和失败项 | 修订、保存、继续、导出 |

不只验收空白首页。没有任务和资料时使用真实空状态；不给空库填上虚构任务、人物数量或记忆增长曲线。

## 6. 视觉与内容规则

- 黑白配色、默认深色、官方 neutral 令牌。应用外壳保持中性，个人照片和视频保留原始颜色。
- 沿用 Geist，正文主要使用 14–16px，辅助标签通常不小于 12px；不使用大量 10px 文字表达关键状态。
- 通过对齐、间距、字重和内容分区体现层级。列表适合连续活动，卡片用于独立结果，避免每句话和每次调用都套边框。
- 主操作明确，次要动作在 hover、菜单或详情中出现，兼顾键盘和触屏。
- 页面只使用帮助用户操作或判断状态的文案，不放架构说明和宣传段落。
- 功能完整性以可走通的任务和可验证的数据为准，不以导航项、按钮或组件数量为准。

实施顺序与验收见 [工作台改造计划](../plans/0003-agent-workspace.md)。
