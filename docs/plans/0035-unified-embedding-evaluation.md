# 阶段三十五：统一文字与图像嵌入的本机评估

> 本文保留当时的模型评测和迁移分析。后续产品方向已明确为用户配置服务接口，模型不作为项目固定选型；当前接入方式见[特征服务说明](../local-memory-processing.md)。

关联核心任务：M2 组织资料、M3 查找资料与回忆经历。

状态：真实 CPU / GPU 编码器对照及视频帧检查完成。结果支持采用 EmbeddingGemma 2 的文字＋视觉模块统一替代 E5 与 SigLIP2，优先 GPU 部署；正式工作台接入和索引迁移尚未执行。

## 目标与范围

用户希望实际尝试 EmbeddingGemma 2，判断能否用一个本地模型替代 multilingual-e5-small 与 SigLIP2；YuNet/SFace 人脸处理独立保留。

本轮先在隔离环境运行真实编码器对照，检查文字、中文图文及同空间混合检索。产品的关键词检索、人物与时间过滤、确认规则、版本失效和原件关联继续属于业务服务；统一编码器不能替代这些规则。音频、完整视频片段理解、个人参数记忆训练不在本轮验收中。

## 固定配置与验收口径

- 基线：仓库 `services/memory-worker/models.json` 固定的 E5 384 维、SigLIP2 768 维 ONNX int8，CPU 推理。
- 候选：`google/embeddinggemma-2`，版本 `914f7f89142e33e77833254d9c9b90c3cef7303b`，Apache-2.0。仅加载文字与视觉，输出 768 维。CPU 使用 FP32，查询 `SearchQuery`、记录 `Document`、图像不添加文字提示；都进行 L2 归一化。不使用 FP16。
- 推理环境：独立 Python 环境，CPU / GPU 依赖锁分别位于 `examples/quality/embedding-environment/uv.lock` 和 `examples/quality/embedding-gpu-environment/uv.lock`。权重下载单独执行，推理本地加载并禁用 Hugging Face 联网，不调用外部生成模型。
- 素材：既有 `retrieval.json` 的 41 条虚构记录和 `images.json` 的 18 张有许可原图。存在纠正的记录使用更正后的正文；编码器只收到文字正文或定向 RGB 像素，不接收图片来源说明、人物真名标签或参考答案。
- 32 道文字题中，28 道有答案、3 道未知、1 道人物歧义；未知与歧义不计入命中率。16 道图像题来自 8 个物体场景，每个场景两种问法，不算 16 个独立场景。
- 所有题都在全部 41 条文字或全部 18 张图像上排名，不应用业务过滤或关键词。与阶段十五分批引入候选的产品融合结果口径不同。历史 `development` / `holdout` 标签仅用于分组，材料均已公开给开发者，本轮是回归对照，不称盲评。
- 候选额外将 41 条文字和 18 张图像放入同一个 768 维空间，用同一个查询编码方式检索；分别报告文字、图像和混合成绩，不以维度相同证明排序可靠。
- 保存逐题名次、Top-5、向量、清单与实现摘要、依赖版本、模型加载时间、预热后逐条查询时间、图像索引时间和进程峰值内存。耗时是单次诊断数据，不是吞吐量或大规模延迟保证。

## 实现与部署边界

`examples/quality/download-embeddinggemma2.py` 下载固定公共模型，校验固定权重 SHA-256，并保存各文件摘要。大文件支持有界并行分段与完成片段续传。模型、下载片段、向量和报告只保存在忽略的 `.data/`。

`examples/quality/evaluate-embedding-backends.py` 对两种真实编码器使用同一评分流程。基线文字调用现有 worker，图像复用其固定预处理与 ONNX 计算方式，排除与本次比较无关的人脸推理。候选通过官方 Sentence Transformers / Transformers 接口加载，不启用远端代码。真实模型结果与产品接入、数据库迁移验收分别记录。

正式替换至少需要适配 `integrations/local-features.ts` 的维度校验、`memory/vectors.ts` 的文字向量表、worker 模型配置与推理入口；现有代码固定文字 384 维。新旧模型即便同为 768 维也不能混用。迁移应在新索引中重建文字、原文及图像/视频帧向量，核对当前来源与版本后切换，并保留回退条件。人脸仍使用自己的编码器与身份确认规则。

还发现现有 `memory/graph.ts:recordImage` 将整套处理器的 `fingerprint` 用于人脸观察 ID，`faceCandidates` 也按同一指纹筛选。仅更换文字/视觉模型会使旧人脸观察和确认关联无法直接复用。因此正式迁移须拆分语义编码器与人脸版本边界，验证旧人物确认、合并/拆分决定及视频人物关联仍有效。不能仅保留 SFace 权重就宣称人物数据不受影响。同空间查询也应复用一次查询编码，避免现有文字与 `image_text` 两次调用重复执行同一个模型。

## 实际结果

2026-10-07 在本机 i7-11800H、WSL2、约 16 GB 可见内存上运行真实模型。候选实际加载 438,760,448 个参数，关闭音频；FP32，CPU 计算线程为 2。图片使用各自官方预处理，原件内容与 EXIF 定向一致，不为了模型替换重写参考答案。

| 纯向量回归 | E5 / SigLIP2：第一条 / 前三条 | EmbeddingGemma 2 CPU：第一条 / 前三条 |
| --- | --- | --- |
| 中文文字，28 道有答案题 | 25/28、28/28 | 26/28、28/28 |
| 中文找图，16 道问题 | 10/16、15/16 | 16/16、16/16 |

图像六道原 Top-1 失败题全部改善，其余题没有倒退。例如“黑色双柄锅盛着宽面条”从第九变为第一；绿色杯碟、俯拍杯碟和透明小壶等细节查询也改善。文字只改善一道近似运单号问题；取件码 KQ7M、运单 YT72049186 仍排第二，说明精确编号匹配依然需要业务检索规则。

候选把两类资料不加条件地放在同一个池中时，44 道有答案题仅 36 道第一、41 道前三；各自通道合计为 42 道第一、44 道前三。部分找图问题被文字记录挤出，如白杯蓝线问题降到第十七、黑碗与筷子降到第二十六。统一编码器可行，不应因此移除资料类型路由、过滤与结果融合。

| 本机单次 CPU 诊断 | E5＋SigLIP2 ONNX int8 | EmbeddingGemma 2 FP32 |
| --- | --- | --- |
| 文字查询编码中位时间 | 3.37 ms | 94.86 ms |
| 找图查询编码中位时间 | 22.74 ms | 116.19 ms |
| 单图编码中位时间，含读取和预处理 | 120.50 ms | 7,549.98 ms |
| 进程峰值 RSS | 1,369.68 MiB | 2,959.05 MiB |

模型精度、运行框架及预处理不同，这是当前可用部署方式对照，不把耗时差全部归因于模型架构。CPU 路径可运行，但批量照片及视频帧维护代价明显增加。

### GPU 实测

本机 NVIDIA GeForce RTX 3050 Ti Laptop GPU，4,096 MiB 显存，驱动 576.83。使用 PyTorch 2.11.0+cu128、torchvision 0.26.0+cu128、Sentence Transformers 6.1.0、Transformers 5.19.0；BF16，逐条编码，预热后计时。该驱动走 CUDA 12.8 运行库；独立 CPU 环境使用 PyTorch 2.14.1+cpu。GPU 所有已安装包版本与锁文件一致，依赖检查通过。

GPU 的文字、图像、混合检索逐题名次与 CPU 完全一致，仍是 26/28、16/16、36/44 Top-1；两组输入清单摘要相同。CPU / GPU 对应向量的最低余弦约 0.99987，没有通过改题或重排调参维持成绩。

| 本机 GPU 单次诊断 | 结果 |
| --- | --- |
| 文字查询编码中位时间 / P95 | 56.32 / 91.89 ms |
| 找图查询编码中位时间 / P95 | 62.24 / 82.28 ms |
| 单图编码中位时间，含读取和预处理 | 285.98 ms |
| PyTorch 峰值已分配 / 预留显存 | 931.81 / 972.00 MiB |
| 进程峰值 RSS | 2,746.35 MiB |

该小批量配置已实际在 4 GB 显存内完成，比候选 CPU 图片路径快约 26 倍。查询编码和单图编码仍慢于原先小型 ONNX 编码器；采用理由是图像召回改善、统一编码及后续多模态扩展，不宣称全面加速。PyTorch 显存统计不包含全部驱动上下文；这里也没有验证 8K 上下文、多图混合输入或服务并发下的峰值。

### 视频抽帧检查

另使用 `examples/videos/manifest.json` 中两段已校验的公有领域视频，分别在请求时间 0、2、4 秒抽帧。对照原始像素固定了 `embedding-video-queries.json` 的四个中文场景描述，再运行两种编码器；六帧均通过真实图像编码，基线和候选都是 4/4 Top-1 找到对应视频的帧。该检查只说明候选可承担当前抽帧检索用途，不证明动作、声音、完整视频或精确时间定位效果。

报告为 `embedding-legacy-cpu-ond1uu5c/report.json`、`embedding-embeddinggemma2-cpu-fra8j6xo/report.json`；GPU 复测 `embedding-embeddinggemma2-cuda-itj84m12/report.json` 也为 4/4 Top-1。`--video-only` 可复跑，使用固定源视频摘要，报告保留请求时间、抽取帧摘要及来源许可。

## 决策与交付

本轮支持进入正式替换：以同一个 EmbeddingGemma 2 文字＋视觉模型生成 768 维文字、原文、图片和视频帧向量，优先使用本机 GPU BF16。保留 YuNet/SFace、关键词和精确编号匹配、资料类型路由、人物/日期/版本过滤及融合。一个编码器不等于一个无条件混排的结果池。

交付包括固定模型下载器、CPU / GPU 独立依赖锁、两种真实编码器共用的回归脚本、固定视频场景问题、原始报告及复现说明。验证包含实际加载、向量有限性与归一化、同题排名、视频帧、两套依赖锁与 GPU 包一致性检查、脚本语法及差异格式检查。没有使用向量测试替身，也没有修改正式服务，因此未把本轮结果描述为工作台集成通过。

正式接入仍须完成上述维度与指纹适配、可回退的索引重建，并验证来源停用、纠正、旧人物确认、合并/拆分与视频人物关联。现有小样本结果不能代替个人相册大样本或新材料的独立评估。
