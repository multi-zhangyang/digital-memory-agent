# 阶段三十六：人脸模型的本机 GPU 替换评估

> 本文保留当时的模型评测和迁移分析。后续产品方向已明确为用户配置服务接口，模型不作为项目固定选型；当前接入方式见[特征服务说明](../local-memory-processing.md)。

关联核心任务：M2 组织资料中的人物出现、M3 按人物查找照片和视频帧。

状态：SCRFD-2.5GF / SCRFD-10GF＋ArcFace R50 的真实 GPU 对照及与
EmbeddingGemma 2 共同驻留检查完成。支持本机部署和进入适配阶段；正式
worker、向量表、人物关联及工作台尚未切换。没有调用外部视觉模型或启动训练。

## 实现与配置

- 基线直接调用正式 `Worker.faces()`：YuNet 320/640/1280 多尺度检测，
  检测阈值 0.9、NMS 0.3，SFace 128 维，CPU。
- 候选为官方 v0.7 发布包 `buffalo_m` / `buffalo_l` 中带五点关键点的
  SCRFD-2.5GF / SCRFD-10GF，以及 ResNet50@WebFace600K（ArcFace，512 维）。
  两包中的 R50 权重已逐字节核对一致；不加载性别、年龄或密集关键点模型。
- 固定上游代码提交 `3e6486942a1be2da0e5b475fac375ea73264bd21`，原样使用
  SCRFD 解码、五点对齐和 ArcFace 预处理。仅生成空包入口，避免整包自动下载
  和无关模块导入。代码 MIT；官方预训练权重限非商业研究，商业用途需另行授权。
- 候选检测输入 640×640，检测阈值 0.5、NMS 0.4；两条路径均限制原图最大边
  1600、最小可用脸 32 像素、最多 32 脸。输出均为有限、L2 归一化向量。
- `face-models.json` 固定发布包、提取权重、代码、许可的大小和 SHA-256。
  下载器可续传并校验摘要；推理脚本只读本地缓存。权重和原始输出在 `.data/`。
- 独立 Python 3.12 环境固定 ONNX Runtime GPU 1.24.4、CUDA 12 运行库、
  cuDNN 9.19.0.56。锁定的 39 个已安装包版本全部一致，依赖检查通过。
  部分大型 wheel 复用本地已下载文件或按锁定 URL 分段下载后校验；没有改系统驱动。

候选使用 FP32 ONNX，保留 CUDA EP 默认 TF32 配置。卷积算法选择 HEURISTIC，
每个 session 的 GPU arena 上限配置为 1 GiB，按请求大小扩展，不启用最大
cuDNN workspace。该 arena 限额不是整个进程显存的硬上限。

GPU 请求在 provider 初始化失败时直接报错，禁用运行时静默回退。预热 profiling
证实两个模型的卷积、矩阵计算在 CUDA 上执行；SCRFD 另有 Slice、Gather、
Unsqueeze、Concat 在 CPU 上处理形状。图片缩放、后处理和对齐仍在 CPU。
profiling 结束后才测耗时。上游对齐函数与当前 scikit-image 的已知弃用提示
在适配入口精确过滤，未改对齐算法，也未屏蔽推理失败。

## 实际运行与效果

2026-10-07，本机 i7-11800H、WSL2、RTX 3050 Ti Laptop，4096 MiB 显存，
驱动 576.83。串行处理，每张预热后的原图执行三次。计时包含缩放、检测、
对齐和特征提取，不含文件解码和模型加载；不同图片原始分辨率不同。

| 当前公开样本对照 | YuNet＋SFace CPU | SCRFD-2.5GF＋R50 GPU | SCRFD-10GF＋R50 GPU |
| --- | --- | --- | --- |
| 人脸数量符合参考的原图 | 18/18 | 18/18 | 18/18 |
| 8 张物体照片误检 | 0 | 0 | 0 |
| 同人配对通过 | 5/5 | 5/5 | 5/5 |
| 异人配对通过 | 23/23 | 23/23 | 23/23 |
| 全部原图处理耗时中位数 | 104.65 ms | 49.36 ms | 62.61 ms |
| 10 张含人照片处理耗时中位数 | 134.97 ms | 53.05 ms | 63.69 ms |
| 采样整卡显存最高值 | — | 447 MiB | 531 MiB |

照片为历史固定集：8 张物体、8 张独立肖像、2 张合影。已对照各方案的带框
预览检查人脸位置，不能只靠数量一致认定定位正确。第一张低分辨率合影的
4 张脸均低于 32 像素，三个方案都不生成识别向量；第二张合影 5 张脸均可用。
人物配对只用 8 张单人照片，匿名参考组不提供给模型。

配对共用照片，不是 28 个独立场景。开发部分为 2 对同人、8 对异人；历史
保留部分为 3 对同人、15 对异人。基线沿用 0.55；候选按开发部分的最小同人
分数与最大异人分数中点确定实验阈值，2.5GF 为 0.37668，10GF 为 0.37349。
保留题未参与阈值选择。这些阈值仅供本次实验，不能直接用于正式身份关联。

原图同人最小值／异人最大值：基线约 0.64380／0.25402；2.5GF＋R50 约
0.70176／0.07994；10GF＋R50 约 0.71387／0.08150。新模型在这组照片上的
分数分隔更明显，但不同模型的余弦尺度不同，这不等于普遍准确率提高。

另对 10GF＋R50 显式运行 CPU 对照。原图与派生图的检出数、可用脸数、配对
及候选匹配决定与 GPU 全部一致；对应的 33 个向量最低余弦约 0.99989。
含人照片处理耗时中位数约 337.70 ms，相比 GPU 的 63.69 ms 明显更慢，
支持优先 GPU。此处只验证显式 CPU 选项，没有给正式服务加入自动回退。

### 派生图片压力测试

固定对 8 张肖像执行三类变换：最长边缩至 160 像素、亮度乘 0.25、两者组合。
这些是原件的派生像素，不是新拍摄，也不能代表真实夜景、侧脸、遮挡或年龄变化。
三个方案在每种变换中都检出 8/8 张脸。

人物匹配图库排除同一张来源照片，只与其他拍摄比较；有另一张同人照片的
探针共 7 张。采用各自实验阈值，并要求与其他人物的次优分数差至少 0.1。
这是编码器层面的候选匹配检查，没有运行正式人物图谱和确认流程。

| 成功关联到另一张同人照片 | YuNet＋SFace | 2.5GF＋R50 | 10GF＋R50 |
| --- | --- | --- | --- |
| 缩小 | 6/7 | 5/7 | 5/7 |
| 变暗 | 7/7 | 7/7 | 7/7 |
| 缩小并变暗 | 5/7 | 5/7 | 5/7 |

上述未成功项均因尺寸规则未生成向量；可用探针均正确，没有误关联其他人物。
单独缩小时，`person-d-1` 在 YuNet 下脸宽约 33.16 像素，在两个 SCRFD 下
分别约 29.88 / 30.37 像素。沿用 32 像素门槛使新方案少进入一次匹配。
该差异已保留，未通过降低门槛重算成绩。正式适配必须重新验证质量门槛，
不能把相同框尺寸阈值当作不同检测器之间完全等价的质量标准。

### 与统一嵌入模型共同驻留

两个进程分别保留 EmbeddingGemma 2 BF16 和 SCRFD-10GF＋R50 GPU session，
在同一张五人合影上交替执行三轮图片编码和人脸处理。

- EmbeddingGemma 2 单独驻留并完成图片／查询编码后整卡约 1061 MiB。
- 两套模型完成预热后约 1592 MiB，交替运行期间观测最高 1608 MiB。
- 每轮均产生 5 张可用人脸；图像编码重复结果余弦约 1.0，查询向量为 768 维。
- 人脸三轮约 124.60 / 116.19 / 111.81 ms，图像编码约
  336.69 / 293.23 / 286.22 ms；这是一张五人合影，不能与上表全图库中位数混用。

结果证明当前小批量、串行维护任务可以在 4 GB 显存内让两套模型共同驻留。
显存为整卡观测值，可能遗漏瞬时峰值；没有验证大批量、多个请求并行、
长上下文或其他 GPU 应用同时运行的峰值。

## 决策与正式迁移条件

本机 GPU 可运行，建议把 **SCRFD-10GF＋ArcFace R50** 作为准确率优先的
接入候选，保留 2.5GF 作为速度对照。当前样本两种检测器效果相同，10GF
优先级结合官方困难人脸基准与本机可接受成本，不宣称本次已经测出准确率优势。
与 EmbeddingGemma 2 共同驻留也已验证，显卡容量不是当前替换障碍。

正式替换不能只修改两个 ONNX 文件：

1. 人脸协议与 `memory/vectors.ts` 当前固定 128 维，需要支持新的 512 维
   命名空间和可回退的新索引；新旧人脸向量不能互相比较。
2. 将语义编码器与人脸处理版本拆分。当前全局 fingerprint 参与观察 ID 和
   候选查询，语义模型替换也可能改变人物关联边界。
3. 保留已确认人物及合并／拆分决定，将重检测后的出现区域映射回原件和
   视频时间位置；不得清空已有确认后重新猜测身份。
4. 重新标定匹配阈值、次优差值和小脸质量规则，并使用更多独立真实困难照片
   检查漏检、误检、错误合并及不确定状态。现有样本不足以保证全面提高准确率。
